# 一条文档记录支持多个文件的功能规划

Last updated: 2026-06-23

## 1. 需求理解

用户明确提出：文档管理中，一个客户合同可能包含多个文件，所以一条记录中需要支持上传多个文件，并且对每个文件分别描述。

这是 FileAdmin 的核心数据模型要求。

## 2. 业务解释

在真实派遣、猎头、IT 服务业务中，“合同”通常不是单个文件，而是一个业务文件包。

例如，一个客户合同包可能包含：

1. 基本契约书。
2. 个别契约书。
3. NDA。
4. 补充协议。
5. 单价表。
6. 盖章扫描件。
7. 邮件确认 PDF。
8. 法务修改版 Word。
9. 最新正式发出版 PDF。

如果系统只支持一条记录上传一个文件，会产生以下问题：

- 同一客户合同被拆成多条记录，难以查询。
- 到期提醒无法知道哪些文件属于同一合同关系。
- 版本混乱，无法判断正式版。
- 审计难以追踪。
- 销售、HR、法务、财务看到的信息不一致。

因此，FileAdmin 采用“文档记录 + 多文件附件”的设计。

## 3. 核心对象

### 3.1 Document Record 文档记录

表示业务上的一组文件，例如：

- 某客户的人材紹介基本契约。
- 某客户的派遣基本契约。
- 某个 IT 项目的業務委託契約文件包。
- 公司对外发布的服务说明书。

文档记录负责管理业务属性：

- 客户。
- 业务类型。
- 文档类别。
- 合同开始日 / 结束日。
- 到期提醒。
- 负责人。
- 状态。
- 访问权限。

### 3.2 File Attachment 文件附件

表示实际上传的一个文件。

每个文件附件有独立属性：

- 文件标题。
- 文件说明。
- 文件类型。
- 文件路径。
- 原始文件名。
- 文件扩展名。
- 文件大小。
- 上传人。
- 上传时间。
- 版本号。
- 是否当前有效版本。
- 是否正式签署版。
- 文件语言。
- 保密等级。
- 文件级有效期。

## 4. 推荐页面交互

### 4.1 文档记录详情页

详情页上方显示合同包 / 文档包整体信息：

- 文档编号。
- 客户名称。
- 文档标题。
- 业务线：派遣 / 人材紹介 / RPO / IT 服务 / 内部管理。
- 文档类别。
- 合同期间。
- 到期提醒状态。
- 负责人。
- 当前状态。

下方显示“文件附件列表”：

| 文件标题 | 类型 | 版本 | 当前有效 | 签署版 | 语言 | 上传人 | 上传时间 | 操作 |
|---|---|---:|---|---|---|---|---|---|
| 基本契约书 | Contract Main | v1 | 是 | 是 | 日本语 | admin | 2026-06-23 | 查看 / 下载 / 编辑说明 |
| 单价补充协议 | Amendment | v1 | 是 | 是 | 日本语 | admin | 2026-06-23 | 查看 / 下载 / 编辑说明 |
| 法务修改版 | Review Draft | v2 | 否 | 否 | 日本语 | admin | 2026-06-23 | 查看 / 下载 / 归档 |

### 4.2 上传多个文件

上传区域支持：

- 一次选择多个文件。
- 每个文件上传后必须补充独立描述。
- 可为每个文件选择文件类型。
- 可为每个文件设置版本号。
- 可标记是否为当前有效文件。
- 可标记是否为已签署 / 已盖章正式版。

### 4.3 文件级描述字段

每个文件建议至少填写：

- 文件显示标题。
- 文件说明。
- 文件类型。
- 版本号。
- 是否当前有效。
- 是否正式签署版。

可选填写：

- 文件语言。
- 保密等级。
- 文件级有效期。
- 对应合同条款备注。
- 与其他文件的关系说明。

## 5. 到期提醒如何处理

到期提醒有两层：

### 5.1 文档记录级到期

适合合同整体到期提醒。

例如：客户 A 派遣基本契约 2027-03-31 到期。

### 5.2 文件附件级到期

适合某个附件单独到期。

例如：

- NDA 有效期 3 年。
- 个别契约每 3 个月更新。
- 单价表只适用于 2026 财年。
- 派遣抵触日相关文件需要单独提醒。

MVP 阶段建议先做记录级提醒，同时在数据模型中预留附件级提醒字段。

## 6. 版本管理规则

### 6.1 文档记录版本

文档记录可有整体 revision，例如 R1、R2，用于表示整个合同包的业务更新。

### 6.2 文件版本

每个文件单独版本管理，例如：

- 基本契约书 v1。
- 基本契约书 v2 法务修正版。
- 基本契约书 v3 双方签署版。

同一文件类型中建议只允许一个 `is_current = true`，避免多个“当前版”。

### 6.3 不删除原则

- 已签署文件不得物理删除。
- 历史版本不得覆盖。
- 如需修正，上传新版本并将旧版本设为非当前。
- 草稿上传错误可允许管理员软删除，但必须保留审计记录。

## 7. MVP 验收标准

第一版完成后，应能完成以下场景：

1. 新建一个客户合同记录。
2. 在该记录下上传多个文件。
3. 对每个文件填写不同说明。
4. 标记哪个文件是正式签署版。
5. 标记哪个文件是当前有效版。
6. 查询客户时能看到完整合同包。
7. 到期提醒能按合同记录显示。
8. 审计日志能看到每个文件的上传和修改记录。
