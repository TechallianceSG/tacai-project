# FileAdmin 企业文件管理设计方案

Last updated: 2026-06-23

## 1. 设计目标

FileAdmin 要解决中小型日本派遣、猎头、RPO、IT 服务公司的文件管理痛点：

1. 合同快到期无人提醒。
2. 客户合同、注文书、报价、NDA 分散在个人电脑/聊天软件/邮件里。
3. 对外文书版本不统一，容易使用旧模板。
4. 不清楚哪个文件是正式版、谁负责、是否已签署。
5. 文件下载、修改、归档缺少审计。
6. 派遣、猎头、IT 服务文件分类混杂，后续开票/合规/审计困难。

## 2. 核心设计原则

### 2.1 轻量但可治理

MVP 不做复杂网盘，而是建立业务台账：

- 文件 metadata 是核心。
- 附件是证据。
- 版本是历史。
- 到期提醒是业务行动。
- 审计是合规底线。

### 2.2 文件与业务对象关联

每个文件尽量关联一个或多个业务对象：

- Entity：所属法人/法律雇主。
- Customer：客户公司。
- Vendor：供应商/外包伙伴。
- Employee：员工/派遣员工；第一阶段只记录引用，不存高敏资料。
- Project：RPO/IT 服务/客户项目。
- Billing：开票/收款依据。
- Timesheet：派遣/SES 工时依据。

MVP 可先用文本字段或外部 ID 字段，后续再与 Master Data/API 连接。

### 2.3 文档记录和文件附件分离

FileAdmin 的核心模型不是“一条记录 = 一个文件”，而是：

```text
一条文档记录 / 合同包 / 文书包
  ├── 文件附件 1：主合同
  ├── 文件附件 2：补充协议
  ├── 文件附件 3：NDA
  ├── 文件附件 4：盖章扫描版
  └── 文件附件 5：邮件确认 PDF
```

文档记录负责业务属性：客户、业务线、合同期间、到期提醒、负责人、状态、权限。

文件附件负责实际文件属性：文件标题、文件说明、文件类型、版本号、是否当前有效、是否签署版、上传人、存储路径、hash。

这样可以支持真实业务中的“一个客户合同包含多个文件”的场景，避免把同一合同拆成多条混乱记录。

### 2.4 版本不可覆盖

上传新版本时：

- 旧文件保留。
- 新增版本记录。
- 标记当前版本。
- 写入变更原因。
- 记录上传人、时间、hash。

### 2.5 合同提醒是任务，不只是日期

合同提醒记录需要包含：

- 触发日期。
- 提醒对象/负责人。
- 提醒原因：到期、自动续约、终止通知期限、价格调整、合规复核。
- 处理结果：未处理、已联系、续约中、不续约、已完成、忽略并说明理由。

### 2.6 对外模板需要发布状态

公司对外模板不是普通附件，必须有：

- 模板编号。
- 语言。
- 适用业务线。
- 当前有效版本。
- 审核人/批准人。
- 生效日/废止日。
- 旧版本只读。

## 3. 模块结构

### 3.1 Dashboard

用途：管理者每日/每周查看风险。

显示：

- 即将到期合同数量。
- 已过期未处理合同数量。
- 近 30 天新增文件数量。
- 当前有效模板数量。
- 待确认提醒。
- 最近上传版本。

### 3.2 文件台账

用途：所有业务文件的主列表。

核心功能：

- 新增文件。
- 按分类、业务线、客户、负责人、状态、到期日筛选。
- 查看详情。
- 归档/恢复。
- CSV 导出。

### 3.3 文件详情

用途：查看一个文件资产的完整信息。

显示：

- 基本信息。
- 业务关联。
- 合同字段。
- 当前版本。
- 历史版本。
- 提醒记录。
- 审计历史。

### 3.4 版本管理

用途：管理正式文书不同版本。

规则：

- 每次上传产生一个 `version_id`。
- 版本号推荐语义：`v1.0`, `v1.1`, `v2.0`。
- `v1.1` 表示小修改；`v2.0` 表示模板/条款大变化。
- 一个 document 同时只能有一个 current version。
- version status：draft / review / approved / active / replaced / archived。

### 3.5 合同提醒

用途：集中处理合同到期和自动续约风险。

提醒类型：

- `contract_expiry`：合同到期。
- `auto_renewal_notice`：自动续约通知期限。
- `termination_notice`：终止通知期限。
- `price_review`：价格/单价调整复核。
- `compliance_review`：派遣/隐私/安全条款复核。

### 3.6 模板库

用途：避免对外文书版本混乱。

模板类型：

- 会社案内。
- 服务说明书。
- 派遣报价书。
- 猎头推荐邮件模板。
- NDA。
- RPO 月报模板。
- IT 服务提案/报价模板。
- 劳务/合规通知模板。

### 3.7 审计日志

用途：满足内部控制和未来合规审计。

必须记录：

- 文件新增。
- metadata 修改。
- 文件版本上传。
- 当前版本切换。
- 状态变更。
- 归档/恢复。
- 提醒确认。
- 权限/保密等级变更。
- 下载/查看敏感文件；MVP 可先记录下载，后续再记录每次查看。

## 4. 信息架构

```text
Dashboard
├── 到期风险
├── 待处理提醒
├── 最近文件
└── 当前模板

Documents
├── 全部文件
├── 客户合同
├── 派遣/HR 合规
├── IT/RPO 项目
├── 报价/订单/验收
├── 对外模板
└── 已归档

Reminders
├── 已过期
├── 7 天内
├── 14 天内
├── 30 天内
├── 60 天内
└── 90 天内

Templates
├── 当前有效模板
├── 待审核模板
├── 历史版本
└── 已废止模板

Audit
└── 操作日志
```

## 5. 文件编号建议

### 5.1 文件资产编号

格式：

```text
FA-YYYY-NNNN
```

示例：

- `FA-2026-0001`

### 5.2 合同编号

格式：

```text
CT-业务线-YYYY-NNNN
```

业务线代码：

- `DISP`：派遣
- `REC`：猎头/人材紹介
- `RPO`：RPO
- `IT`：IT 服务/SES
- `VEN`：供应商/外包

示例：

- `CT-DISP-2026-0001`
- `CT-REC-2026-0002`

### 5.3 模板编号

格式：

```text
TPL-业务线-语言-YYYY-NNNN
```

示例：

- `TPL-DISP-JA-2026-0001`
- `TPL-REC-EN-2026-0002`

## 6. 状态设计

### 6.1 Document Status

| 状态 | 含义 |
|---|---|
| draft | 草稿登记，尚未确认 |
| active | 当前有效 |
| expiring | 即将到期 |
| expired | 已过期 |
| renewed | 已续约，可能有关联新合同 |
| terminated | 已终止 |
| archived | 已归档，只读保留 |

### 6.2 Version Status

| 状态 | 含义 |
|---|---|
| draft | 草稿版本 |
| review | 审核中 |
| approved | 已批准但未生效 |
| active | 当前有效版本 |
| replaced | 已被新版本替代 |
| archived | 历史归档 |

### 6.3 Reminder Status

| 状态 | 含义 |
|---|---|
| open | 未处理 |
| acknowledged | 已确认收到 |
| in_progress | 处理中 |
| completed | 已完成 |
| waived | 不处理/豁免，必须写理由 |

## 7. 权限设计

### 7.1 权限 namespace

```text
fileadmin.access
fileadmin.view
fileadmin.manage
fileadmin.contracts.manage
fileadmin.templates.manage
fileadmin.reminders.manage
fileadmin.audit.view
fileadmin.sensitive.view
fileadmin.download
```

### 7.2 保密等级

| 等级 | 说明 | MVP 控制 |
|---|---|---|
| public_internal | 内部公开 | 登录用户可按权限看 |
| business_confidential | 业务机密 | 业务角色可看 |
| contract_confidential | 合同机密 | 管理者/负责人/Finance/HR 视情况 |
| personal_data | 个人信息 | 严格限制；第一阶段尽量不存 |
| highly_sensitive | 高敏 | MVP 原则上不开放上传；如需上传必须单独审批 |

## 8. 日本派遣与 IT/猎头文件包设计

### 8.1 客户派遣文件包

包含：

- 派遣基本契约。
- 个别契约。
- 注文书/注文请书。
- 労働者派遣通知书。
- 费用/单价调整记录。
- 客户沟通记录附件。

关键字段：

- 派遣期间。
- 客户事业所/工作地点。
- 派遣料金/单价；MVP 可只做文字备注或金额字段。
- 负责人。
- 到期/自动更新/终止通知期限。

### 8.2 猎头客户文件包

包含：

- 人材紹介基本契约。
- 成功报酬条款。
- 返金/Guarantee 条款。
- NDA。
- 客户职位说明/JD。
- 候选人推荐确认附件。

关键字段：

- Fee rate。
- Guarantee period。
- Replacement/refund clause。
- 合同有效期。

### 8.3 RPO 文件包

包含：

- RPO 服务合同。
- SLA。
- 月度报告模板。
- 项目交付物。
- 变更范围记录。

关键字段：

- 项目期间。
- 月费/成功费。
- 交付频率。
- SLA 指标。

### 8.4 IT 服务文件包

包含：

- 準委任/請負/SES 合同。
- 注文书。
- 检收书。
- 项目计划书。
- 交付物。
- 安全/NDA 文件。

关键字段：

- 契约形态。
- 工时/月额/单价。
- 验收条件。
- 再委托条款。
- 交付物清单。

## 9. 轻量上线 UI 建议

沿用 TAC suite 当前风格：

- 顶部 navy header。
- 横向模块导航。
- Dashboard 卡片：到期、过期、待处理、模板。
- 表格列表 + filter toolbar。
- 详情页采用 object-page：标题区、状态 badge、关键字段卡片、版本表、审计表。
- 成功/错误提示使用 message strip。

## 10. 后续扩展方向

- 与 Master Data Customer/Vendor API 自动关联。
- 与 Customer Billing 关联合同和注文作为开票证据。
- 与 Timesheet 关联派遣/SES 个别契约。
- 与 EmployeeAdmin 关联员工普通文件；高敏文件需单独安全设计。
- 加入全文搜索和标签。
- 加入 OCR/AI 摘要/条款抽取。
- 加入外部客户安全共享，但必须先完成访问控制、安全审计和下载水印。
