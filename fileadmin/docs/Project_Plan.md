# FileAdmin 项目计划

Last updated: 2026-06-23

## 1. 项目定位

FileAdmin 是 TACAI 业务套件中的企业文件管理模块，优先服务以下业务：

- 日本派遣业务：派遣基本契约、个别契约、労働者派遣通知書、抵触日相关文件、客户派遣订单、派遣员工相关证明文件。
- 猎头/人材紹介业务：客户基本合同、成功报酬条款、候选人推荐确认、NDA、候选人/客户沟通附件。
- RPO 业务：RPO 服务合同、SLA、招聘项目文档、客户报告模板、月度交付物。
- IT 服务/SES/外包业务：委托合同、準委任/請負合同、注文書、検収書、项目交付物、NDA、报价书。
- 公司通用对外文书：报价模板、服务说明书、会社案内、隐私政策、社内规则、邮件模板、通知模板。

项目核心不是做“网盘”，而是做“有台账、有版本、有责任人、有到期提醒、有审计”的业务文件管理系统。

## 2. 业务视角设计

### 2.1 东京派遣及 IT / 猎头专家视角

#### 必须优先管理的文件

| 业务线 | 文件类型 | 风险点 | MVP 处理方式 |
|---|---|---|---|
| 派遣 | 派遣基本契约 | 合同到期、派遣法合规、自动更新条款 | 合同台账 + 到期提醒 + 客户/Entity 关联 |
| 派遣 | 个别契约/注文書 | 派遣期间、单价、工作地、抵触日关联 | 版本管理 + 关键字段人工录入 |
| 派遣 | 労働者派遣通知書 | 交付/保存证据 | 文件记录 + 上传/下载审计 |
| 猎头 | 人材紹介契约 | 成功报酬、返金条款、有效期 | 条款摘要 + 到期提醒 |
| RPO | RPO 服务合同/SLA | 月度交付、范围变更 | 项目维度版本管理 |
| IT 服务 | SES/準委任/請負合同 | 契约形态、工时/验收、再委托 | 合同分类 + 风险标签 |
| 公司文书 | 对外模板 | 版本混乱、旧模板误用 | 当前有效版本 + 发布状态 |

#### 日本业务合规要点

- 派遣相关文件必须能追踪客户、派遣期间、工作地点、合同版本、负责人和保存状态。
- 对外合同和模板需要区分日文、英文、中文版本，正式使用版本必须有状态标识。
- 客户合同到期、自动更新、提前解约通知期限需要提醒。
- 文件删除不应物理删除，至少 MVP 阶段使用 `archived` / `inactive` 状态。
- 关键字段由人工确认，AI/OCR 只能辅助草稿，不可直接覆盖正式合同台账。

### 2.2 架构专家视角

#### 推荐 MVP 架构

- 技术路线：Python 标准库 Web App + 本地 JSON + 本地文件存储。
- 端口：`8011`。
- 登录：后续接入 User_admin session，不单独做登录系统。
- Portal：后续作为 TACAI Portal 模块入口。
- 文件存储：上传文件保存在 `attachments/`，业务台账只保存 metadata 和相对路径。
- 审计：append-only JSONL 或 JSON array，字段与全局 Audit Rules 一致。
- 不引入复杂 DMS/网盘依赖，避免过早做全文搜索、在线编辑、外部共享。

#### 与现有模块的关系

| 模块 | 关系 |
|---|---|
| TACAI-Core/User_admin | 权限、用户、角色、Entity context 来源 |
| TACAI-Core/masterdata | 后续读取客户、供应商、Entity、部门、项目主数据 |
| TAC-employeeadmin | 后续可关联员工文件，但第一阶段避免处理 My Number 等高敏数据 |
| TAC-timesheet | 派遣个别契约可作为工时/单价/项目依据，但 MVP 不自动计算 |
| TAC-reimbursement | 可关联发票/收据类文件，但报销附件仍由报销模块保存 |
| customerbilling | 合同/注文書可作为开票依据，后续关联客户账单 |
| VendorPayables | 外包供应商合同可作为供应商付款依据 |

### 2.3 文件管理专家视角

#### 文件分类原则

1. 按业务目的分类，不只按文件格式分类。
2. 每个文件必须有责任人、所属 Entity、业务线、状态、版本号。
3. 合同类文件必须有合同期间、提醒规则、对方公司、签署状态。
4. 对外模板必须有“当前有效版本”概念。
5. 任何上传新版本都不覆盖旧文件，只新增版本记录。

#### 推荐分类

- `contract_client_dispatch`：客户派遣合同
- `contract_client_recruitment`：猎头/人材紹介合同
- `contract_rpo`：RPO 合同
- `contract_it_service`：IT 服务/SES/外包合同
- `contract_vendor`：供应商/外包伙伴合同
- `company_external_template`：公司对外模板
- `proposal_quotation`：报价/提案/見積
- `order_acceptance`：注文書/注文請書
- `delivery_acceptance`：纳品/検収/交付物证明
- `compliance_hr_dispatch`：派遣/HR 合规文件
- `internal_policy`：内部规则/SOP
- `other`：其他

## 3. MVP 范围

### 3.1 Phase 0 — 文件夹与规划完成

已完成/本次完成：

- 创建 `fileadmin/` 目录结构。
- 创建项目 README、项目计划、设计方案、数据 schema、实施步骤。
- 初始化本模块 memory 文件。

### 3.2 Phase 1 — 轻量内部台账 MVP

目标：可以登记文件、上传附件、查看版本、看到合同到期提醒。

功能：

- 文件台账列表：按业务线、文件类型、客户、状态、到期日筛选。
- 文件登记：标题、分类、客户/项目/Entity、负责人、保密等级、合同期间、提醒日。
- 附件上传：一条文档记录支持上传多个实际文件，本地保存原文件，记录 hash、文件名、大小、上传人。
- 附件描述：每个文件附件必须可单独填写标题、说明、文件类型、版本号、是否当前有效、是否正式签署版。
- 版本管理：同一文档记录下可存在多个文件；同一文件角色可上传 `v1.0`, `v1.1`, `v2.0` 等版本，保留历史。
- 到期提醒：页面显示 90/60/30/14/7 天内到期合同。
- 状态管理：draft / active / expiring / expired / archived。
- 审计查看：显示最近上传、版本变更、状态变更、提醒确认。

不做：

- 外部客户共享链接。
- 在线 Office/PDF 编辑。
- 自动 OCR 正式入库。
- 大型全文搜索引擎。
- 文件夹级复杂权限继承。

### 3.3 Phase 2 — Portal + User_admin 集成

目标：成为 TACAI Portal 内部模块。

功能：

- Portal 注册 FileAdmin 模块，建议端口 `8011`。
- User_admin 增加权限 namespace：`fileadmin.*`。
- 按角色授权：System Admin、HR Manager、Finance、Sales/Consultant Manager、Document Admin。
- 读取 session 的 Entity context，默认只看本 Entity 文件。
- 增加操作成功提示，保持 TAC-timesheet UI 风格。

### 3.4 Phase 3 — 合同治理与模板治理强化

目标：从“台账”升级为“企业文件治理”。

功能：

- 合同关键条款结构化：自动更新、通知期限、付款条款、返金条款、保密条款。
- 对外模板发布流程：draft → review → approved → active → replaced / archived。
- 当前有效模板页面：防止旧版本误用。
- 合同续约/终止任务清单。
- 客户维度合同包：客户所有有效合同、补充协议、注文书、报价一览。

### 3.5 Phase 4 — 可复用模板自动生成

目标：把高频、可参数化的业务文书从“复制旧文件再手工改”升级为“选择国家 + 选择模板 + 输入参数 + 系统生成草稿 + 人工复核 + 归档审计”。

优先覆盖日本、中国、新加坡运营需求：

- Offer Letter / 内定通知 / 录用通知。
- 猎头 / 人材紹介 / Recruitment Agreement。
- 日本派遣基本契約、個別契約、注文書相关模板。
- RPO 服务合同、NDA、报价/服务说明书。

功能：

- 模板库：按国家、语言、业务线、文件类型、Entity、状态、版本管理模板。
- 参数定义：为每个模板维护必填参数、字段标签、校验规则和来源提示。
- 草稿生成：用参数替换模板占位符，生成 HTML/Markdown 草稿，并保存生成记录。
- 归档联动：生成文件自动进入 FileAdmin DocumentRecord / FileAttachment。
- 人工复核：高风险模板必须复核后才能标记正式使用。
- 审计：模板创建、激活、生成、复核、下载、归档均写 append-only audit log。

详细计划见 `docs/Reusable_Template_Automation_Plan.md`。

### 3.6 Phase 5 — AI/OCR 辅助

目标：提高登记效率，但不替代人工确认。

功能：

- OCR/文本抽取上传合同基本信息草稿。
- 合同到期日、自动更新条款、通知期限建议。
- 文档摘要和风险标签建议。
- 对外模板差异比较。

约束：

- AI 结果必须标记为 `suggested`。
- 人工确认后才进入正式字段。
- 合同原文和个人信息不默认发送到外部 LLM；需确认数据策略。

## 4. 角色与权限建议

| 角色 | 权限范围 |
|---|---|
| System Admin | 全部查看、配置、权限、审计查看 |
| Document Admin | 文件分类、模板、版本、归档、提醒配置 |
| HR Manager | HR/派遣合规文件、员工相关普通文件、派遣合同查看 |
| Sales/Consultant Manager | 客户合同、猎头/RPO/IT 服务合同、报价/注文文件 |
| Finance | 与开票、付款、订单、合同金额相关文件查看 |
| Employee/Consultant | 默认不进入 FileAdmin；如需自助查看，另设只读范围 |

## 5. 风险与控制

| 风险 | 控制 |
|---|---|
| 合同过期未发现 | 到期提醒列表 + 负责人 + 提醒确认 |
| 旧模板被误用 | 当前有效版本标识 + 历史版本只读 |
| 敏感文件泄露 | 权限分级 + 下载审计 + 不做外部共享 MVP |
| 文件覆盖丢失 | 新版本追加，不覆盖旧文件 |
| 台账字段不准 | OCR 仅草稿，关键字段人工确认 |
| 文件越来越乱 | 分类枚举 + 必填 owner/status/entity/business_line |

## 6. 上线判断标准

Phase 1 内部 MVP 可以上线的最低标准：

- 能登记客户合同记录，并在同一记录下上传多个文件附件。
- 每个附件都能单独填写说明、文件类型、版本号、当前有效标记和正式签署标记。
- 能上传同一文件角色的多个版本并看到历史版本。
- 合同到期提醒页面可用。
- 审计日志记录新增、上传、状态变更、版本变更。
- 文件删除不可物理删除，只能归档。
- 至少完成 10 个真实/脱敏文件的试录入。
- HR/Consulting/Finance 各确认一轮字段是否够用。
